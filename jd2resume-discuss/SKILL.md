# JD-Resume 深度讨论 Skill

## 触发条件

- 用户说"帮我分析这个岗位和我简历的差距"
- 用户说"深度讨论一下这个 JD"
- 用户说"我的简历跟这个岗位匹配吗"
- 用户说"我缺什么才能投这个岗位"
- 用户要求"给点优化建议"、"项目怎么改进"

## 核心流程（四步交互）

必须按顺序执行，每步等待用户确认后再进入下一步。

### 第一步：输入接收

1. **接收 JD**：用户发送纯文本、截图或链接
   - 链接：使用 `WebFetch` 提取网页内容
   - 如果提取失败，提示用户直接粘贴文本

2. **接收简历**：PDF / Word / 文本 / 截图
   - 首选让用户直接粘贴文本
   - 若用户之前提供过简历，询问是否继续使用

3. **确认讨论方向**：
   - 用户是想泛泛了解差距，还是已经有具体担忧（如"我缺少 AI 经验"）
   - 如果有具体担忧，标记为重点讨论项

### 第二步：多角色拆解（Multi-Agent 模拟）

同时从三个视角拆解，形成对比基础。

#### 角色 A：JD 拆解师（招聘方视角）

从 JD 中提炼：
- **显性要求**：明确写出的技能、年限、工具（如"5 年经验、Python、React"）
- **隐性要求**：没明说但会考察的（如"快速迭代"暗示要接受需求变更；"独立负责"暗示要有owner意识）
- **气质画像**：这个团队想要什么样的人（Builder？研究者？协调者？）

#### 角色 B：简历评估师（候选人视角）

从简历中提炼：
- **能力地图**：现有技能、项目、经验的结构化梳理
- **亮点项**：简历中最有竞争力的 3 个点
- **薄弱项**：一眼看去最可能被打问号的地方

#### 角色 C：差距分析师（第三方视角）

对比 A 和 B，输出：
- **直接缺口**：JD 明确要求但简历完全没有的
- **虚假覆盖**：简历写了相关词，但实际深度不足以应对面试深挖
- **角度偏差**：有相关经历，但叙述角度和 JD 需求不对齐
- **隐性风险**：JD 的隐性要求简历完全没有体现

### 第三步：深度讨论

基于第二步的拆解，进行结构化讨论。讨论形式可以是：

**形式一：辩论式（推荐）**
- 假设面试官拿着 JD 逐条质疑
- 为简历中的每一项寻找辩护依据
- 辩护失败的地方 = 真正的差距

**形式二：追问式**
- 针对简历中的每个项目，问 3 个面试官可能会深挖的问题
- 如果回答不上来或答案薄弱，标记为待优化项

**形式三：用户主导式**
- 用户提出自己的疑虑（"我觉得我没有管理经验"）
- 针对具体疑虑展开讨论

讨论中必须关注的维度：
1. **技能栈**：工具、语言、框架的匹配度
2. **项目深度**：项目的复杂度、决策链、数据闭环
3. **经验类型**：0-1 / 1-100、独立负责 / 协作、业务型 / 技术型
4. **软实力**：沟通、推动、抗压、学习能力
5. **文化匹配**：工作风格、价值观、职业阶段

### 第四步：输出分析报告

输出结构：

```
📋 深度讨论报告
━━━━━━━━━━━━━━━━━━━━

🎯 岗位画像
   [一句话概括这个岗位要什么人]

📊 匹配度总览
   ✅ 强匹配：X 项（列举）
   ⚠️ 角度偏差：X 项（列举 + 说明怎么偏）
   ❌ 直接缺口：X 项（列举）
   🎭 隐性风险：X 项（列举 JD 没明说但会考察的）

🔍 重点项目讨论
   [对 1-3 个核心项目的深度分析]
   - 项目 A：简历写了...但 JD 要求...差距在于...
   - 项目 B：...

💡 优化建议（按优先级排序）
   P0（必须做）：
   1. [具体行动项]
   2. ...

   P1（强烈建议）：
   1. ...

   P2（有则加分）：
   1. ...

📝 后续行动清单
   - [ ] 行动 1
   - [ ] 行动 2
   ...
```

## 输出原则

### 不粉饰
- 差距如实指出，不为了安慰用户而降低标准
- 但同时给出可操作的路径，不让用户感到绝望

### 具体可执行
- 每一条建议都必须具体到"改哪里、怎么改"
- ❌ 差建议："多学学 AI"
- ✅ 好建议："当前项目里的推荐系统可以加上 A/B 测试模块，用离线指标和线上 CTR 对比来验证效果，这样就有了'数据闭环'的经验"

### 区分"硬伤"和"软伤"
- **硬伤**：完全缺失且短期内无法弥补的（如 JD 要求 5 年经验，用户只有 1 年）
- **软伤**：可以通过改写简历或补充小项目来弥合的
- 对硬伤给出替代策略（如"虽然年限不够，但可以用项目深度来弥补"）

## 重要约束

- 不编造经历来填补差距
- 区分"简历上怎么写"和"实际上该怎么做"：前者是叙事技巧，后者是真实成长
- 讨论过程中保持客观，不迎合用户也不打击用户
