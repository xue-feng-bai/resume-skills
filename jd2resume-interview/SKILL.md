# JD-Resume 面试方案 Skill

## 触发条件

- 用户说"帮我准备面试"
- 用户说"这个岗位面试会问什么"
- 用户说"结合我的简历给点面试建议"
- 用户要求"模拟面试"、"面试问题清单"
- 用户说"我该怎么回答"

## 核心流程（四步交互）

必须按顺序执行，每步等待用户确认后再进入下一步。

### 第一步：输入接收

1. **接收 JD**：纯文本 / 截图 / 链接
   - 链接：使用 `WebFetch` 提取
   - 提取失败则提示用户粘贴文本

2. **接收简历**：PDF / Word / 文本 / 截图
   - 首选让用户直接粘贴文本

3. **确认面试阶段**：
   - 一面（技术面/业务面）
   - 二面（经理面/综合面）
   - 三面（总监面/文化面）
   - HR 面
   - 不同阶段的侧重点不同，必须确认

4. **确认面试形式**（如果有信息）：
   - 线上视频 / 线下面试
   - 有无代码考核 / Case 分析
   - 时长（30min / 1h）

### 第二步：面试画像分析

基于 JD + 简历 + 面试阶段，分析：

#### 1. JD 考察重点
- 这个岗位最核心的 3 个考察维度是什么
- 每个维度的权重预估

#### 2. 简历中的"钩子"
- 面试官看了简历后**一定会追问**的点
- 通常是：数据指标、技术选型、冲突处理、失败经历

#### 3. 潜在风险点
- 简历中容易引发质疑的地方
- 例如：项目时间太短、技术栈太杂、有空白期、跳槽频繁

#### 4. 面试官风格推测
- 从 JD 用词推测：偏业务型、偏技术型、偏文化型

### 第三步：问题清单生成

按类别生成预测问题，每类问题标注"出现概率"和"重要性"。

#### 类别一：项目深挖（概率最高）

基于简历中的每个项目，生成追问链：

**第一层（是什么）**：
- "介绍一下这个项目"
- "你在里面承担什么角色"

**第二层（为什么）**：
- "为什么选这个技术方案，而不是 XXX"
- "当时有没有其他方案，怎么决策的"

**第三层（怎么做）**：
- "具体怎么实现的，遇到的最大技术难点是什么"
- "如果重来一次，你会怎么做"

**第四层（结果与反思）**：
- "项目最后的数据怎么样"
- "最大的收获和遗憾是什么"

#### 类别二：技能验证

基于 JD 要求的硬技能：
- 工具使用深度（"你们是怎么用 Claude Code 的，具体一个场景"）
- 技术原理理解（"你能解释一下 LangGraph 的状态机设计吗"）
- 场景应用（"如果线上出现一个未知 Bug，你的排查思路是什么"）

#### 类别三：行为/文化问题

基于公司类型和 JD 气质：
- "说一个你和同事意见不一致的经历"
- "说一个你失败的项目"
- "你理想的工作环境是什么样的"
- "你为什么离开上一家公司"
- "你对加班怎么看"

#### 类别四：开放/压力问题

- "你觉得你和这个岗位有什么差距"
- "如果给你一个新方向，完全没有经验，你会怎么做"
- "你最近在学习什么"
- "你有什么问题要问我"

### 第四步：回答策略与准备清单

#### 回答策略模板

每个重要问题提供：

```
❓ 问题：...
🎯 考察点：面试官想问什么
📝 建议框架：
   1. ...
   2. ...
   3. ...
📌 可引用的简历素材：
   - "你在 XX 项目里做的 XXX，可以在这里展开"
   - "用数据：XXX"
⚠️ 避坑提示：
   - 不要...
   - 避免...
```

#### 通用回答原则

1. **STAR 法则**：Situation → Task → Action → Result
2. **数据优先**：用具体数字代替"提升了效率"
3. **承认不足 + 展示成长**：被问到不会的，坦诚承认 + 说明学习路径
4. **反问意识**：回答完可以自然反问，展示思考深度

#### 面试准备清单

输出一份可勾选的清单：

```
📋 面试准备清单
━━━━━━━━━━━━━━━━━━━━

资料准备：
- [ ] 打印 2 份简历
- [ ] 准备项目时间线（防止说错时间）
- [ ] 整理每个项目的关键数据

技术准备：
- [ ] 复习 [具体技术点 1]
- [ ] 复习 [具体技术点 2]
- [ ] 准备 1-2 个技术亮点的深入讲解

行为准备：
- [ ] 准备"自我介绍"（1min / 3min 两个版本）
- [ ] 准备"为什么离开上家"
- [ ] 准备"你的优缺点"
- [ ] 准备"职业规划"

提问准备：
- [ ] 准备 3 个反问面试官的问题
   1. ...
   2. ...
   3. ...

模拟演练：
- [ ] 用语音复述一遍项目经历
- [ ] 找人模拟一面/二面
```

## 输出原则

### 不代写答案
- 只给"回答框架"和"可引用的素材"，不给完整标准答案
- 完整答案必须由用户自己组织，否则面试时像背书

### 差异化
- 不同公司、不同岗位、不同阶段的面试策略完全不同
- 必须基于具体 JD 和简历生成，不能给通用模板

### 风险提示
- 对简历中的风险点必须提前预警，并给出应对策略
- 例如跳槽频繁 → 准备"职业规划一致性"的故事

## 重要约束

- 不编造项目细节来匹配面试问题
- 区分"面试时怎么答"和"实际上该怎么做"：前者是沟通策略，后者是真实能力
- 保持客观，不为了鼓励用户而淡化真实风险
