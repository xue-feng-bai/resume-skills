# JD-Resume 一站式套件 Skill

## 触发条件

- 用户说"全流程"、"一条龙"、"从头到尾"
- 用户说"帮我走完整个求职准备"
- 用户说"分析、改简历、面试准备都要"
- 用户要求"求职总方案"

## 核心定位

本 Skill 是 `jd2resume-discuss` → `jd2resume` → `jd2resume-interview` 的串联编排器。

**不重复造轮子**：每个阶段的具体执行逻辑，直接复用对应子 Skill 的流程和约束。
本 Skill 只负责三件事：
1. **顺序控制**：按正确顺序执行三个阶段
2. **数据流转**：前一阶段的输出作为后一阶段的输入
3. **总览整合**：最终给用户一份完整的求职准备总报告

## 数据流转关系

```
用户输入：JD + 简历
    ↓
Phase 1: 深度讨论 (jd2resume-discuss)
    → 输出：差距分析报告 + P0/P1/P2 优化建议
    → 关键流转项：P0 建议清单（流入 Phase 2）
    ↓
Phase 2: 简历优化 (jd2resume)
    → 输入：JD + 简历 + Phase 1 的 P0 建议
    → 输出：优化后的简历文本 + HTML/PDF/截图文件
    → 关键流转项：优化后的简历内容（流入 Phase 3）
    ↓
Phase 3: 面试方案 (jd2resume-interview)
    → 输入：JD + Phase 2 优化后的简历 + 面试阶段
    → 输出：面试问题清单 + 回答策略 + 准备清单
    ↓
总输出：求职准备总报告（三阶段成果汇总）
```

## 核心流程（四步交互）

### 第一步：统一输入

1. **接收 JD**：纯文本 / 截图 / 链接
   - 使用 `WebFetch` 提取链接内容
   - 失败则提示用户粘贴文本

2. **接收简历**：PDF / Word / 文本 / 截图
   - 首选让用户直接粘贴文本

3. **确认面试阶段**（为 Phase 3 做准备）：
   - 一面 / 二面 / 三面 / HR 面
   - 如果用户不确定，先不填，进入 Phase 1 后再确认

4. **告知用户完整流程**：
   ```
   📋 一站式求职准备流程
   ━━━━━━━━━━━━━━━━━━━━
   Phase 1: 深度讨论 — 分析简历与岗位的差距
   Phase 2: 简历优化 — 根据讨论结果优化简历
   Phase 3: 面试方案 — 基于优化后的简历准备面试

   每阶段结束后你可以选择：继续 / 调整 / 跳过
   是否开始？（是/否）
   ```

### 第二步：Phase 1 — 深度讨论

**直接复用 `jd2resume-discuss` 的核心流程**：

1. 多角色拆解（JD 拆解师 + 简历评估师 + 差距分析师）
2. 深度讨论（辩论式 / 追问式 / 用户主导式）
3. 输出差距分析报告

**本阶段额外要求**：
- 输出时必须**显式标注 P0 建议清单**，因为这是流入 Phase 2 的关键数据
- 标注格式：
  ```
  📌 P0 建议清单（将直接用于简历优化）
  1. [具体建议]
  2. [具体建议]
  ...
  ```

**用户选择权**：
- 确认继续 → 进入 Phase 2
- 要求调整 → 回到 Phase 1 重新讨论
- 跳过 Phase 2 → 直接进入 Phase 3（使用原始简历）

### 第三步：Phase 2 — 简历优化

**直接复用 `jd2resume` 的核心流程**，但输入增加 Phase 1 的 P0 建议：

1. **匹配与调整**
   - JD 关键词对比
   - 额外输入：Phase 1 的 P0 建议清单（必须优先处理）

2. **生成优化方案**
   - 计划修改中必须包含 P0 建议的对应项

3. **用户确认**
   - 展示修改计划，包含"来自 Phase 1 讨论的建议"标注

4. **生成输出**
   - 优化后的简历文本
   - HTML / PDF / 截图文件（默认保存到 `./output/`）

**本阶段额外要求**：
- 优化后的简历文本必须**完整保留**，作为 Phase 3 的输入

**用户选择权**：
- 确认继续 → 进入 Phase 3
- 要求调整 → 回到 Phase 2 修改简历
- 跳过 Phase 3 → 流程结束，只输出简历

### 第四步：Phase 3 — 面试方案

**直接复用 `jd2resume-interview` 的核心流程**，但输入使用 Phase 2 优化后的简历：

1. **面试画像分析**
   - JD 考察重点
   - 简历中的"钩子"（基于**优化后的简历**）
   - 潜在风险点

2. **问题清单生成**
   - 项目深挖、技能验证、行为/文化、开放/压力

3. **回答策略与准备清单**
   - 每个问题的考察点、建议框架、可引用素材、避坑提示

**用户选择权**：
- 确认完成 → 进入总报告输出
- 要求调整 → 回到 Phase 3 修改面试方案

### 第五步：总报告输出

整合三个阶段的成果，输出一份完整的求职准备总报告：

```
📋 求职准备总报告
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【岗位信息】
- 岗位：...
- 本质：...

【Phase 1: 差距分析摘要】
✅ 强匹配：X 项
⚠️ 角度偏差：X 项
❌ 直接缺口：X 项
🎭 隐性风险：X 项

【Phase 2: 简历优化摘要】
- 修改了 X 处
- 核心调整：...
- 文件位置：./output/简历_...html

【Phase 3: 面试准备摘要】
- 预测问题数：X 个
- 高风险追问点：...
- 必须准备的行为问题：...

【下一步行动】
- [ ] 根据 P0 建议补充项目（如果还有未完成的）
- [ ] 用语音复述一遍项目经历
- [ ] 模拟面试至少 1 次
- [ ] 准备 3 个反问面试官的问题
```

## 约束继承

本 Skill 必须同时遵守三个子 Skill 的所有约束：

### 来自 jd2resume-discuss
- 不粉饰差距，如实指出
- 建议必须具体可执行
- 区分硬伤和软伤

### 来自 jd2resume
- 不编造经历
- 保留事实，只调整叙述角度
- 每次新 JD 必须重新确认简历
- 避免表格形式，接地气风格

### 来自 jd2resume-interview
- 不代写完整答案，只给框架
- 差异化策略，不给通用模板
- 对风险点提前预警

## 跳过机制

用户可以在任意阶段选择跳过下一阶段：
- 跳过 Phase 2：用原始简历直接进入面试准备
- 跳过 Phase 3：只输出差距分析和优化简历
- 如果用户明确说"只要讨论"或"只要面试"，直接引导到对应子 Skill，不走本套件流程

## 错误处理

| 场景 | 处理方式 |
|------|---------|
| Phase 1 无法解析 JD | 提示用户粘贴文本，跳过关键词提取，继续讨论 |
| Phase 2 脚本生成失败 | 输出 HTML 让用户手动打印，面试方案基于文本版简历继续 |
| Phase 3 用户未确认面试阶段 | 默认按"一面"生成通用方案，提示用户后续可按具体阶段再细化 |
| 用户中途想退出 | 保存当前阶段成果，输出阶段性报告 |
