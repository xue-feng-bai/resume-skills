# Resume Polish Skill

## 触发条件

- 用户说"帮我看看简历"、"优化一下简历"
- 用户发送简历文件或文本，要求改进
- 用户说"我的简历有什么问题"
- 用户要求"生成 HTML/PDF/截图 简历"

## 核心流程（五步交互）

必须按顺序执行，每步等待用户确认后再进入下一步。

### 第一步：简历输入

1. **接收简历**：PDF / Word / 文本 / 截图
   - 首选让用户直接粘贴文本
   - PDF/截图：尝试提取文字，失败则请用户分段粘贴

2. **确认求职目标**（简短）：
   - 用户目前想投什么方向？（如"AI 产品经理"、"后端开发"）
   - 这是判断"卖点是否突出"和"格式推荐"的关键依据，不需要完整 JD

### 第二步：简历自检（五维度扫描）

基于专业简历标准，从五个维度扫描简历质量问题。

#### 维度一：零错误与基础规范（P0）

**硬性标准，必须全部通过。**

- **错别字与语法**：常见错误如"的/得/地"、"做/作"、英文大小写不一致
- **联系方式完整性**：手机、邮箱是否齐全且格式正确
- **时间格式统一**：全用 `2022.03 - 2024.05` 或全用 `2022/03 - 2024/05`，禁止混用
- **时间线冲突**：两段经历是否有重叠（除非注明兼职）
- **时间线空白**：是否有超过 3 个月无法解释的空白期

#### 维度二：结构完整性（P0）

- **头部信息**：姓名、联系方式、求职目标
- **Profile/Summary**：是否有 3-4 行的核心总结（可选但强烈推荐）
- **核心经历**：工作经历或项目经历至少有一个，且内容不为空
- **教育背景**：学校、专业、时间是否齐全

#### 维度三：叙事质量（P1）

**这是简历质量的分水岭。**

- **动词强度**：
  - ❌ 弱动词：参与、协助、负责相关工作、使用、了解
  - ✅ 强动词：识别、推动、主导、搭建、设计、验证、重构、优化、落地、迭代
- **量化程度**：每条核心经历是否包含数字、百分比、时间、规模
  - ❌ "提升了系统性能"
  - ✅ "将接口响应时间从 500ms 降低到 50ms，QPS 提升 10 倍"
- **职责 vs 成果比例**：
  - 职责描述应 ≤ 30%，成果描述应 ≥ 70%
  - ❌ "负责后台管理系统开发"（纯职责）
  - ✅ "识别后台管理流程人工审核效率低的痛点，设计并落地自动化审批系统，将平均处理时间从 2 天缩短至 2 小时"
- **决策链 vs 功能清单**：
  - ❌ "项目包含用户端、管理端、数据看板"
  - ✅ "从运营人员'无法实时追踪活动效果'的痛点出发，设计实时数据看板，覆盖 5 大核心指标..."
- **空话/套话检测**：
 - 绝对删除："具备良好的沟通能力和团队协作精神"、"工作认真负责"、"学习能力强"
  - 替换策略：用具体事例替代形容词

#### 维度四：卖点突出度（P1）

- **Profile 精准度**：是否在 3-4 行内概括了"我是谁 + 我擅长什么 + 我能带来什么"
- **经历排序**：最有竞争力的经历是否放在最前面
- **钩子密度**：是否有 2-3 个能引起面试官追问的点（有深度但不展开）
- **信息密度**：是否每条 bullet 都有独立价值，没有重复或填充内容

#### 维度五：逻辑一致性（P1）

- **技能与经历匹配**：简历中声称掌握的技能，是否有对应的项目/工作经历支撑
- **成果合理性**：数据是否经得起追问（如"提升 1000%"是否有前提条件）
- **角色与成果匹配**：初级岗位却写了大量战略级决策，需要验证合理性

### 第三步：输出优化建议清单

按 P0/P1/P2 分级输出，每个问题附带具体修改建议。

```
📋 简历自检报告
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【P0 — 必须修复】
1. [具体问题] → [修改建议]
2. ...

【P1 — 强烈建议】
1. [具体问题] → [修改建议]
2. ...

【P2 — 锦上添花】
1. [具体问题] → [修改建议]
2. ...

📐 格式推荐
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
基于你的简历情况，推荐采用：
[标准版 / 转行版]

理由：...

标准版顺序：Profile → 工作经历 → 项目经历 → 教育背景
转行版顺序：Profile → 项目经历 → 工作经历 → 教育背景
（适用场景：工作经历与目标岗位关联度低，但项目经历高度相关）
```

### 第四步：写作套路对话选择

根据简历的类型、行业、以及第三步发现的叙事问题，推荐最适合的写作套路。

**可选套路：**

**A. STAR 法则**
- 适用：项目经历丰富、每个项目有完整故事线的候选人
- 结构：Situation（背景）→ Task（任务）→ Action（行动）→ Result（结果）
- 特点：最完整，适合深挖型面试

**B. CAR 法则**
- 适用：工作年限较长、经历较多需要精简的候选人
- 结构：Context（上下文）→ Action（行动）→ Result（结果）
- 特点：比 STAR 更简洁，适合 bullet point 写法

**C. PAR 法则**
- 适用：技术/产品岗，强调解决问题能力的候选人
- 结构：Problem（问题）→ Action（行动）→ Result（结果）
- 特点：突出痛点识别和解决能力，最能体现"主动找活干"

**D. 量化优先法**
- 适用：数据岗、运营岗、增长岗等结果高度可量化的候选人
- 核心：每条 bullet 以数字开头或包含核心数字
- 特点：HR 扫描效率最高，5 秒抓住眼球

**推荐逻辑：**
- 如果简历以项目为主、项目之间有明确故事线 → 推荐 **A. STAR**
- 如果工作经历多、每条需要极度精简 → 推荐 **B. CAR**
- 如果是技术/产品岗、强调解决复杂问题 → 推荐 **C. PAR**（通常最推荐）
- 如果是数据/运营/增长岗、数字密集 → 推荐 **D. 量化优先**

**对话形式：**
```
根据你的简历情况，我推荐采用 [套路 X]，理由是：...

其他可选方案：
- A. STAR：适合...，如果你...可以选这个
- B. CAR：适合...，如果你...可以选这个
- C. PAR：适合...，如果你...可以选这个
- D. 量化优先：适合...，如果你...可以选这个

你确认使用 [推荐套路] 吗？（是 / 我想选 X / 解释一下区别）
```

确认后，将该套路作为后续改写的核心框架。

### 第五步：逐条确认与优化（多轮交互）

**核心机制**：不按套路一次性全改，而是将每个修改点拆解为"原写法 vs 建议写法"，逐项让用户确认。

**交互方式（含降级方案）**：
- **主路径（Claude Code 环境）**：使用 `AskUserQuestion` 工具呈现选项，用户直接点击选择
- **降级路径（其他 AI 工具环境）**：以纯文本形式展示选项，用户回复数字 `1` / `2` / `3` 或关键词 `ok` / `keep` / `custom`
- 两个路径的输出格式必须保持一致，仅交互方式不同

---

#### 第一轮：逐条展示与确认

按 **P0 → P1 → P2** 的顺序逐个展示修改项。每个修改项必须包含：

1. **原来的写法**：必须是**完整的原句子**，不能是片段或关键词
2. **修改后的写法**：基于第四步选定的写作套路，给出**完整的建议句子**
3. **修改理由**：一句话说明为什么这样改
4. **用户选择**：
   - `[1] 接受建议` — 应用建议写法
   - `[2] 保持原写法` — 不做修改
   - `[3] 提供其他方案` — 用户直接输入自己的版本

**单条展示与确认方式**：

展示格式：
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
修改项 3 / 12 【P1 · 叙事质量 · 工作经历】

📝 原写法：
"负责用户增长策略的开发与优化，推动业务数据提升。"

✏️ 建议写法：
"识别新客获取成本过高的痛点，设计并落地邀请返利机制，3 个月内将新客获客成本从 150 元降低至 80 元，月新增用户提升 40%。"

💡 修改理由：
将弱动词"负责"替换为"识别"和"设计并落地"，并补充具体数据与对比基准。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

确认方式：
- **必须使用 `AskUserQuestion` 工具**呈现选项，让用户直接选择
- 选项设计：
  - **接受建议** — 应用建议写法
  - **保持原写法** — 不做修改
  - **提供其他方案** — 用户手动输入自己的版本

**处理逻辑**：
- 选"接受建议"：记录为 ✅ 已接受，应用建议写法
- 选"保持原写法"：记录为 ❌ 已拒绝，保持原写法
- 选"提供其他方案"：弹出文本输入框，用户输入自定义版本。记录为 ✍️ 自定义，应用用户提供的版本（必须也是完整句子）

**降级路径格式（纯文本交互）**：
```
❓ 请选择（回复数字或关键词）：
[1] 接受建议 (ok)
[2] 保持原写法 (keep)
[3] 提供其他方案 (custom)
```

---

#### 第一轮结束：状态汇总

所有修改项确认完毕后，输出汇总：

```
📋 第一轮确认完成
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 已接受：X 项
❌ 已拒绝：X 项
✍️ 自定义：X 项

需要重新讨论的项：
- 项 3（工作经历第 2 条）：用户自定义版本
- 项 7（项目经历第 1 条）：已拒绝
```

**使用 `AskUserQuestion` 询问下一步**：
- 选项设计：
  - **确认完成，生成最终简历** — 进入第六步
  - **对某些项进行第二轮讨论** — 要求用户输入编号
  - **查看已接受/已拒绝/自定义的完整清单** — 列出所有项的状态

**降级路径格式（纯文本交互）**：
```
❓ 请选择（回复数字或关键词）：
[1] 确认完成，生成最终简历 (done)
[2] 对某些项进行第二轮讨论 (retry)
[3] 查看完整清单 (list)
```

---

#### 第二轮及以后（可选）

- 只展示用户指定要重新讨论的项
- 格式与第一轮相同
- 对于"已拒绝"的项，可以给出**替代方案**（第二版建议写法）
- 对于"自定义"的项，可以基于用户版本做**微调建议**
- 可以无限轮次，直到用户说"确认完成"

**第二轮示例**：
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
修改项 3 / 12 · 第二轮 【P1 · 叙事质量 · 工作经历】

📝 原写法：
"负责用户增长策略的开发与优化，推动业务数据提升。"

✏️ 上一轮结果：已拒绝
💡 替代方案：
"主导新客增长策略从 0 到 1 搭建，通过裂变活动与渠道优化双管齐下，实现月新增用户从 5 万提升至 8 万。"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**使用 `AskUserQuestion` 呈现选项**：
- 选项设计：
  - **接受替代方案** — 应用第二版建议
  - **保持原写法** — 仍不做修改
  - **提供其他方案** — 用户手动输入自己的版本

**降级路径格式（纯文本交互）**：
```
❓ 请选择（回复数字或关键词）：
[1] 接受替代方案 (ok)
[2] 保持原写法 (keep)
[3] 提供其他方案 (custom)
```

---

#### 确认完成：生成优化简历文本

用户说"确认完成"后：

1. **组装最终简历文本**：
   - 只应用状态为"✅ 已接受"或"✍️ 自定义"的修改
   - "❌ 已拒绝"的项保持原写法
   - 按第三步推荐的格式顺序（标准版/转行版）排列

2. **最终文本展示**：
   - 以结构化文本展示完整优化后的简历
   - 让用户做最后一次整体确认

3. **用户最终确认后**，进入第六步生成文件

---

### 第六步：生成输出文件

1. **生成三格式文件**：
   - HTML：使用 `scripts/generate_html_resume.py`
   - PDF：使用 `scripts/html_to_pdf.py`
   - 长截图：使用 `scripts/screenshot_resume.py`

2. **文件输出**：默认保存到 `./output/`
   - 命名：`简历_{姓名}.{格式}`

## 自检红线（一票否决项）

以下问题发现任意一个，必须在报告中置顶标红：

1. 联系方式缺失或错误
2. 时间线存在无法解释的 6 个月以上空白
3. 两段经历时间重叠但未注明兼职
4. 存在明显错别字（如姓名、公司名、学校名写错）
5. 所有 bullet point 都是职责描述，零成果
6. 简历完全没有任何数字/量化信息

## 输出原则

### 专注内容，不操心样式
- 只优化文字内容和结构顺序
- 字体、边距、颜色等排版问题交由后续脚本和模板自动处理
- 不评价视觉设计，只评价信息架构

### 具体可执行
- 每条建议必须具体到"改哪一句、怎么改"
- ❌ 差建议："多写点成果"
- ✅ 好建议："第二段工作经历的第一条 bullet，把'负责用户增长'改为'识别新客获取成本过高的痛点，设计并落地邀请返利机制，3 个月内将新客获客成本从 150 元降低至 80 元'"

### 保留事实
- 不编造不存在的经历
- 不夸大未做过的事情
- 可以调整叙述角度，但时间、公司、职责框架不变

## 脚本使用

```bash
# 1. 生成 HTML（需要先准备 JSON 数据文件）
python3 scripts/generate_html_resume.py --input resume_data.json --output resume.html

# 2. HTML → PDF
python3 scripts/html_to_pdf.py --input resume.html --output resume.pdf

# 3. HTML → 长截图（精确裁剪，无空白）
python3 scripts/screenshot_resume.py --input resume.html --output resume.png
```

JSON 数据格式参考 `assets/resume-template.html` 中的变量结构。
